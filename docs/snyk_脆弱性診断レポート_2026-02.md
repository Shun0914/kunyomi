# Snyk 脆弱性診断レポート（2026年2月）

## 概要

Snyk による依存関係の脆弱性診断が行われ、フロントエンド・バックエンドそれぞれに対応する修正 PR が自動作成されました。本ドキュメントは、そのフロー・診断結果・実施した対策をまとめたものです。

※ 本プロジェクトでは Snyk（スニーク）を脆弱性診断ツールとして利用しています。「Sync」は Snyk の誤記です。

---

## 1. フロー（流れ）

```
[Snyk がリポジトリをスキャン]
        ↓
[脆弱性を検出]
        ↓
[修正用 PR を自動作成]
        ↓
  ┌────┴────┐
  │         │
PR #113   PR #114
(backend) (frontend)
  │         │
  │         └→ テスト Pass → マージ
  │
  └→ Security check Fail（新規 CVE 導入）
       ↓
     手動対応（後述）
       ↓
     PR #113 はクローズ、main に直接コミット
```

1. **Snyk のスキャン**  
   リポジトリに連携された Snyk が、npm（frontend）と pip（backend）の依存関係をスキャン。

2. **PR の自動作成**  
   検出された脆弱性を解消するため、以下の 2 本の PR が Snyk により自動作成された。
   - **PR #113**: バックエンド（`backend/requirements.txt`）
   - **PR #114**: フロントエンド（`frontend/package.json`, `package-lock.json`）

3. **フロントエンド（PR #114）**  
   テストがすべて Pass したため、そのままマージ。

4. **バックエンド（PR #113）**  
   PR の Security check が「Newly introduced issues only」で Fail。  
   本 PR で導入するバージョン（cryptography 42.0.0）に新たな CVE が含まれていたため、PR はマージせずクローズし、**main 側で手動対応**した。

---

## 2. 診断結果（何を指摘されたか）

### 2.1 フロントエンド（PR #114）

| 深刻度 | 内容 | Snyk ID | 修正方法 |
|--------|------|---------|----------|
| High | Allocation of Resources Without Limits or Throttling（リソース制限なし） | SNYK-JS-NEXT-15104645 | Next.js のバージョンアップ |
| High | 同上 | SNYK-JS-NEXT-15105315 | 同上 |

- **対象パッケージ**: `next` 16.1.1 → **16.1.5**
- **変更ファイル**: `frontend/package.json`, `frontend/package-lock.json`

### 2.2 バックエンド（PR #113）

| パッケージ | 変更 | 関連する脆弱性タイプ（Snyk 記載） |
|------------|------|----------------------------------|
| pymysql | 1.1.0 → 1.1.1 | SQL Injection 等 |
| cryptography | 41.0.7 → 42.0.0 | 複数 CVE 対応 |
| zipp | （間接依存）3.15.0 → 3.19.1 以上 | DoS（リソース消費）等 |

- **変更ファイル**: `backend/requirements.txt`

**※ バックエンド PR の問題点**  
PR #113 では cryptography を **42.0.0** に上げていたが、42.0.0 には別の脆弱性が存在することが Security check で検出された。
- **CVE-2024-12797**（Missing Report of Error Condition / CWE-392）
- CVSS 6.3（Medium）
- 修正版: **cryptography@44.0.1**

そのため「この PR で新規に導入される問題が 1 件ある」と判定され、PR の Security check が Fail となった。

---

## 3. 実施した対策

### 3.1 フロントエンド

- **PR #114 をマージ**  
  Snyk が提案した通り、Next.js を 16.1.1 → 16.1.5 に更新。  
  テストはすべて Pass していたため、そのままマージして対応完了。

### 3.2 バックエンド

- **PR #113 はマージせずクローズ**  
  理由をコメントで記載したうえでクローズ。
  - コメント要旨: cryptography 42.0.0 で CVE-2024-12797 が「新規導入」として検出されたため、main 側で cryptography を 44.0.1 以上にした内容で対応する旨。

- **main に直接コミットした内容**（`backend/requirements.txt`）:

| パッケージ | 修正後 |
|------------|--------|
| pymysql | 1.1.1 |
| cryptography | **>=44.0.1**（CVE-2024-12797 を解消） |
| zipp | >=3.19.1 |

- コミットメッセージ例:  
  `fix: backend deps - pymysql 1.1.1, cryptography>=44.0.1, zipp (Snyk + CVE-2024-12797)`

これにより、Snyk で指摘されていた既存の脆弱性に加え、CVE-2024-12797 も解消した状態で main を更新した。

## 4. 今後の運用の目安

- **Snyk の PR は「マージするだけ」でよい場合が多い**  
  ただし、Security check が Fail した場合は、  
  -  PR の変更で「新規に導入される CVE」がないか確認する。  
  -  必要に応じて、修正版バージョンまで上げるなど手動で対応し、PR はクローズして main に直接反映する、という流れが有効。

- **マージ or 反映後のローカル**  
  - フロント: `cd frontend && npm install`  
  - バック: `cd backend && pip install -r requirements.txt`  
  で依存関係を更新すること。
