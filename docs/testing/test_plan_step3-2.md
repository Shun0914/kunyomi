# Step3-2 テスト実施プラン

## 概要

「くんよみ」社内ナレッジ管理システムに対して、単体・結合・受け入れテストを実施するための進め方プランです。
**1〜2機能に絞って**効率的に進めることを想定しています。

---

## ① テスト対象の整理（1〜2機能に絞る）

### 候補機能と選定理由

| 機能 | 選定理由 | リスク |
|------|----------|--------|
| **役立ち度スコア計算** | `helpful_count / view_count` の計算ロジック。ソート順・表示に直結。計算ミスはユーザー体験に直撃 | 高 |
| **ドキュメント作成のバリデーション** | キーワード3個制限・必須チェック。不正データの保存を防ぐ入口 | 高 |
| **ドキュメント評価（重複防止）** | 同一ユーザーが複数回評価できないこと。防げないとスコアが歪む | 中 |

### 推奨：1〜2本に絞る場合

**パターンA（1本）**: 役立ち度スコア計算のみ  
- 単体テストが書きやすく、計算ロジックが明確
- バックエンドの `documents.py` に集約されている

**パターンB（2本）**: 役立ち度スコア + ドキュメント作成バリデーション  
- データ保存・表示の両方の重要箇所をカバー
- 単体テストはスキーマ（`DocumentCreateRequest`）とロジック（スコア計算）で分けられる

---

## ② 単体テストの計画（最低2本：正常系1 + 異常系1）

### 技術選定
- **バックエンド**: Python → **Pytest** を使用
- `backend/requirements.txt` に `pytest` を追加

### テスト対象1: 役立ち度スコア計算

| # | 種別 | テスト内容 | 期待値 |
|---|------|------------|--------|
| 1 | 正常系 | `helpful_count=5`, `view_count=10` の場合 | `helpfulness_score = 0.50` |
| 2 | 異常系 | `view_count=0` の場合（ゼロ除算対策） | `helpfulness_score = 0.00`（`max(view_count, 1)` で1として計算） |

**実装方針**: `documents.py` のスコア計算部分を関数化するか、API エンドポイント経由でテストする。

### テスト対象2: ドキュメント作成バリデーション（2本目にする場合）

| # | 種別 | テスト内容 | 期待値 |
|---|------|------------|--------|
| 1 | 正常系 | タイトル・本文・ジャンル・キーワード3個以内で作成 | バリデーション通過 |
| 2 | 異常系 | キーワード4個以上で作成 | `ValueError: キーワードは最大3個までです` |

**実装方針**: `DocumentCreateRequest` スキーマの `validate_keywords` を直接テストする。

---

## ③ 結合テスト（E2E / Playwright）の計画（1本）

### 技術選定
- **Playwright** を使用（フロントエンドは Vite/React）
- `frontend_figma` または `frontend` に Playwright を導入

### 主要シナリオ（1本）

**シナリオ例**: ドキュメント一覧 → 詳細表示 → 評価

1. `http://localhost:3000/document-list` にアクセス
2. ドキュメント一覧が表示されるのを待つ
3. 1件目のドキュメントをクリック
4. 詳細画面で「役立った」ボタンをクリック
5. 評価が反映されていることを確認（スコア表示の変化など）

**参考**: 既存の `docs/testing/e2e_test_cases_week1.md`, `e2e_test_cases_week2.md` の TC-005, TC-201 をベースに自動化する。

---

## ④ 受け入れテストの実施

### やり方
- 自分がユーザーになったつもりで、アプリを**手動で一通り触る**
- 「要件通りに動いているか？」の観点でチェック

### チェック観点（例）
- ドキュメント一覧が正しく表示されるか
- ジャンルフィルタ・キーワード検索が動くか
- ドキュメント作成ができるか（必須項目・キーワード制限）
- 評価（役立った/そうでもない）が記録されるか
- 役立ち度スコアが妥当に表示されるか
- 気づいた違和感・バグをメモする

## 進め方の目安（1〜2本に絞る場合）

| 順番 | タスク | 所要時間の目安 |
|------|--------|----------------|
| 1 | テスト対象を1つ決める（役立ち度スコア推奨） | 10分 |
| 2 | Pytest を導入し、単体テスト2本を書く | 30〜60分 |
| 3 | Playwright を導入し、E2E 1本を書く | 30〜60分 |

**合計**: 約2時間程度で完了可能（環境構築がスムーズな場合）

## 実行方法（実装済み）

### 単体テスト（Pytest）
```bash
cd backend
pip install -r requirements.txt
PYTHONPATH=. python3 -m pytest tests/test_documents_create.py -v
```

- 異常系・スキーマテスト: DB不要（SQLite使用）
- 正常系APIテスト: MySQL環境（DATABASE_URL設定時）で実行

### 結合テスト（Playwright）
```bash
# 1. フロントエンド・バックエンドを起動
# ターミナル1: cd backend && uvicorn app.main:app --reload --port 8000
# ターミナル2: cd frontend && npm run dev

# 2. 別ターミナルでE2Eテスト実行
cd frontend
npm install
npx playwright install
npm run test:e2e
```

### 受け入れテスト
`docs/testing/acceptance_test_checklist_document_create.md` のチェックリストに沿って手動で実施。
